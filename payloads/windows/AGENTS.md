# AGENTS.md —— 部署指令（唯一执行入口）

你在部署「新知识库」Obsidian 维护体系。**照这份文件执行就能一次跑通；不要凭空发明步骤。** 每一步都写明：做什么、怎么判断成功、失败怎么办。

## 0. 触发条件

使用者会对你说类似：「请把我这个 GitHub 项目部署到我电脑上：`<仓库 URL>`。按项目里的部署指令从零开始一键配置，遇到需要授权的地方给我授权一次，其余步骤请自动完成，最后验证是否部署成功。」

你只需要：**识别平台 → 跑一次 `deploy.py` → 把脚本提出的问题转述给使用者 → 按它的输出完成收尾 → 报告结果**。不要凭空发明步骤，也不要替使用者做未经确认的选择。

## 1. 准备：拿到项目

- 从仓库：`git clone <仓库 URL>`，进入仓库根目录（有 `deploy.py` 的那一层）。
- 从压缩包：解压 `release/新知识库部署-macOS-v1.1.0.zip`，进入解压出的顶层目录。
- 判断：`ls` 看到 `deploy.py` 就对了。看不到就在 `release/` 里解压对应平台包再进去。
- 当前仓库只发布 macOS 包；如果使用者是 Windows，先说明"Windows 版本暂未发布"，不要强行继续。

## 2. 识别平台

- macOS：`sys.platform == "darwin"`，跑 `python3 deploy.py`。
- Windows：暂不发布；若拿到 Windows 包，优先 `py deploy.py`，不行就用 `python deploy.py`。
- `deploy.py` 内部会再次自动识别并走对应分支；你不需要替它判断，但必须确认输出里打印的平台与你所在系统一致。

## 3. 运行、问答与授权

- 运行后脚本会**先自检前置条件**并打印缺失项的**现成修复命令**（如 `brew install poppler ffmpeg`）。缺什么就照它给的命令装，然后重跑。**不要自己另找替代命令，也不要跳过检查。**
- 自检通过后，脚本会按顺序问几个问题，**你把问题转述给使用者，由使用者决定**：
  1. **整理时间**：每天整理几次、分别在几点（可直接回车用默认 08/11/14/17/20/23；使用者可以说"每天 3 次、9 点 12 点 18 点"这类大白话）。
  2. **整理模型**：DeepSeek（推荐，只需 API 密钥）/ ChatGPT 桌面版 / 两者组合 / 自定义 OpenAI 兼容模型。
  3. **模型密钥**（选了 API 模型时）：脚本会在本机终端显示隐藏输入提示。让使用者直接在终端键入；**禁止让使用者把密钥发到聊天里，禁止把密钥拼进命令行参数、环境变量或文件。** 密钥只经标准输入交给 macOS 钥匙串。已有钥匙串密钥可直接回车；没有可用密钥时部署验收会失败。
- 问答结束后，脚本会打印一份**完整动作清单**（安装位置、Vault 路径、整理时间、模型、将创建的任务），并只问一次「是否允许？」。**把这份清单转述给使用者，请他授权一次。** 拿到授权（回答 y）后脚本自动完成其余全部步骤，不要再逐步请示。
- 若使用者拒绝：停止，报告拒绝原因，退出。不要绕过授权。
- 授权后仍可能出现系统级弹窗（钥匙串访问、xcode-select 安装、可能的密码输入），这些属于系统授权，提示使用者点一下/输一次即可。

## 4. 安装过程（脚本自动完成，你只监控）

- **macOS**：原子更新 `settings.json` 中由部署管理的时间、模型和路径，再只根据该配置渲染定时任务 → 复制程序 → 建 Vault 骨架（只创建缺失目录，绝不覆盖已有内容）→ 安装 LaunchAgent（先测试与编译、失败自动回滚）→ 将隐藏输入的密钥写入钥匙串。
- **Windows**（后续版本）：检查 Vault 必须为空（**非空立即停止并报告现状，绝不继续**）→ 复制目录骨架与插件（已存在的文件一律跳过，绝不覆盖）→ 把分类/标签配置放进 Vault 规范目录 → 注册定时任务。

## 5. 定时任务

- macOS：LaunchAgent 按部署时设定的时点运行（默认每天 08/11/14/17/20/23 六次、本机时区、不补跑、无加载即运行）。装好后确认 `launchctl print gui/<uid>/com.knowledgevault.obsidian-maintenance` 显示已加载且下次运行时间符合设定。
- 使用者以后想改时间：重跑 `deploy.py`（幂等）并回答新的时间即可；或改 `配置/settings.json` 的 `run_hours` 后重装任务。

## 6. 验收自测（必须真实执行并输出结果）

`deploy.py` 会自动执行并打印验收结果；你再补上 GUI 部分：

- **文件级（脚本自动）**：编译检查、自动测试、Vault 目录骨架完整（taxonomy 全部目录）、定时任务时点正确、launchctl 已加载、临时验收笔记创建→读取→删除、健康审计，以及**模型可用性冒烟测试**（至少一个已配置模型能真正返回结果）。
- **任何健康审计失败或模型不可用时部署都不会成功**：脚本会明确红叉并退出 5。发布版不存在跳过健康审计或模型验证的参数；**不得绕过、不得谎称通过。**
- **GUI 级（你补做）**：请使用者打开 Obsidian 一次；新建一篇笔记到 `00 收件箱`，确认属性面板出现 `created`、`modified`、`kind/note`、`workflow/inbox`；验证后删除该笔记。无法操作 GUI 时如实说明这一步未验证，**不得谎称通过**。

## 7. 失败怎么办

- 任何一步失败：**先读脚本打印的失败原因**，它已定位到具体步骤并给出下一次的正确行为。常见三类：
  1. 缺前置依赖 → 装脚本给出的命令，重跑（幂等，重跑不会叠坏）。
  2. 模型不可用 → 请使用者在本机终端隐藏输入 API 密钥（或安装并登录 ChatGPT 桌面版），重跑；不得让使用者把密钥发到聊天里。
  3. 任务/插件验收失败 → 报告脚本输出，把「已装好什么、差什么」讲清楚。
- **禁止**：绕过检查、静默覆盖已有文件、把密钥写进 Vault、在未授权时把资料发给模型、替使用者选择模型或时间、声称成功但验收没跑完。

## 8. 最终报告格式（给使用者的大白话）

1. 平台与版本：已部署到 macOS，版本 v1.1.0。
2. 整理时间：每天几次、分别在几点（下次运行时间）。
3. 模型：用哪个模型整理的（若用了 API 模型，密钥已写入钥匙串）。
4. 模板：目录骨架与维护规范是否装好。
5. 插件：本地插件是否就位、是否启用。
6. 验收：编译/测试/目录/定时/模型冒烟/临时笔记的验证结果。
7. 未完成项：列出任何需要使用者处理的事（如「请打开一次 Obsidian 并确认插件生效」）。

## 9. 日常运行红线（部署后同样适用）

以 Vault 内 `90 系统/92 维护规范/` 为最高规则：只整理稳定超过 10 分钟的收件箱资料；完整内容默认保全；不自动合并、删除、改目录、改核心结论或写 `20 工作/29 SOP`；高影响事项请求使用者明确决定；不得把 API 密钥、账号令牌、个人资料或运行日志写进 Vault；不得把资料发给任何未启用、未确认的模型或外部服务。
