分类时先判断内容以后主要拿来做什么，再选择一个主存放位置。其他领域通过 Wikilinks 关联，不复制多份正文。

独立 PDF 依据文件标题和可本地提取的正文（扫描件依赖 Windows 上实际启用的本地文字识别能力）选择主目录后，原始 PDF 直接移入该目录，作为长期正式资料。不得为 PDF 生成、重排或转写 Markdown 笔记，也不得改动 PDF 内容或版式；无法提取足以分类的文字时留在收件箱。带 Markdown 明确引用的 PDF 资料包仍遵循附件保全和不自动合并规则。

无法确定位置时保留在收件箱，不创建“其他”“杂项”等永久分类。新增、合并、重命名或删除目录属于高影响操作，必须经本人明确授权；自动整理只记录未执行事项，不使用 Vault 内勾选确认。

工作中，项目过程资料进入项目与任务，专业资料进入专业领域，经验进入复盘与经验，成熟后再回写 SOP。

`20 工作/29 SOP` 是本人维护区。普通工作资料、个案经验和阶段复盘仍先进入 `21–28`；只有本人认为某个专题、典型案例话题或反复出现的问题已经积累了足够经验，才亲自总结到 `29 SOP`。AI 不得把收件箱资料直接归入该目录，也不得新建、移动、续写、改写或合并其中笔记。

目录决定笔记的主归档位置；跨目录检索和待处理提示使用《标签与属性规范》中的受控标签，不以标签复制目录结构。

`90 系统/95 原始输入归档` 按归档日期存放 7 天追溯副本。独立文件直接放入日期目录，同日重名使用 ` (2)`、` (3)`；只有本人批准的多文件资料包才建立可读文件夹。归档完成后，Markdown 原页自动获得未勾选的 `no_delete` 属性；只有本人勾选才不自动删除，其他归档满 7 天后移入系统废纸篓。内部哈希只记录在日期目录下 `.preservation/<bundle_id>.json`，不作为人工浏览的目录名。

源 Markdown 已有合法 `created` 时，新正式笔记继承该捕获时间。原件保留期单独从实际归档时间 `archived_at` 起算，不得用笔记的 `created` 提前启动清理倒计时。
