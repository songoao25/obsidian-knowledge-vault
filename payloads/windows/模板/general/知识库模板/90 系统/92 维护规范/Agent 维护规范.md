这是知识库维护的权威行为规范。本机使用的任何 Agent 都必须遵守。

1. 先读完一次收集的全部文字、链接和附件，再判断它们之间的关系。
2. 区分本人分析、外部摘录、原始资料和 AI 推断。无法判断归属时优先保留。
3. 最大程度保留本人的观点、论证、细节、例子和语气，不擅自改变结论。
4. 先搜索已有目录、同义主题和相关笔记，再决定新建、更新、关联或建议合并。
5. 正文按内容自然组织，不机械套用“摘要、核心要点、总结”，不为了完整添加空栏目。
6. 输入中已有的完整原始 URL、原始附件和可核验来源必须保留，不得缩短、替换或编造；图片、图片说明、音频/视频链接、iframe 嵌入和明确关联的本地附件同样属于原始内容，必须在正式笔记中保留。没有 URL 的网页剪藏仍可正常整理，不得因此拒绝处理。不编造事实、经历、情绪、趋势、法律结论、医疗结论或投资建议。
7. 每个收件箱文件默认独立整理、独立归档。Markdown 或 Wikilink 明确引用属于强关系证据，但所有多文件资料包仍须本人确认；同批放入、文件名相近或主题相似都不是合并依据。模型关系建议还必须达到 0.92 置信度并给出至少两条强证据；拒绝后按原件哈希记住决定，下次逐文件整理。
8. 不创建空白页、占位页和为图谱数量而建立的无意义链接。
9. 目录调整、正式笔记合并、重要删除、核心结论改变、10 篇以上批量变更、25% 以上行级改写、规则或模型变更必须经本人明确授权。自动整理不得执行这类操作，只在 `90 系统/94 维护记录/94.4 高影响操作记录` 留下“未执行”审计记录。
10. 不使用 Vault 内的待确认目录、复选框或审批队列。任何不确定性都应提升风险等级，并保持资料不动。
11. 写入必须幂等、原子化、可恢复；失败不移动原始输入，不留半成品。
12. 属性与标签遵循《标签与属性规范》和《标签词表》；未知标签只报告，不得自行删除、合并或改写语义标签。
13. 本项目有新功能、规则、流程、配置、时间或重要修复时，必须在《规则变更记录》写完整事实、在《知识库使用说明》写通俗解释；两份文件只做对应章节的增量更新，不大面积覆盖仍有效内容。
14. 本 Vault 不是开发工作目录，只保存知识内容和 Obsidian 配置。Agent 不得在 Vault 根目录或其 `docs/` 中写入设计、实施计划、调试输出或其他开发产物；这些内容也不得另建平行文档，已生效的事实只更新《规则变更记录》和对应维护规范。
15. 整理前必须先把输入判断为完整网页文章、个人长分析、碎片记录或其他完整资料。网页文章、个人长分析和其他完整资料默认保全；只有高置信度碎片才可重新组织。标签已明确内容类型时以标签为保全底线；无法确定时保全。
16. 正式笔记必须成为可独立阅读的长期版本：每篇只有一个文档级标题，由 Obsidian 文件名承担。保全型内容只可清理开头重复题头与校正标题层级，不得以摘要、重写或归档替代原有正文和媒体。碎片可整理排版，但人名、地名、时间、金额、数字、条件、例外、URL 和待办含义不得丢失。
17. 原始输入归档仅作 7 天追溯副本，绝不能是唯一保存位置。独立文件直接放在日期目录；只有本人批准的多文件资料包使用文件夹。归档完成后，Markdown 原页必须获得默认未勾选的 `no_delete` 属性；只有本人勾选该属性才不自动清理。其他原件在明确的归档时间满 7 天后移入系统废纸篓，不得再要求本人确认或以完整性校验阻止清理。
19. Windows 部署副本的模型与外部服务由该副本的使用者自行在实际使用的 Agent 中启用和确认。未获使用者明确许可时，不得把收件箱内容发送到外部模型或服务；模型只可返回建议，不能绕过本规范直接操作资料。纯视觉资料没有文本证据时不得要求文本模型猜测。
18. 本人要求检查、审查、核对或审计时，默认完整核对真实 Vault、程序、配置、插件、模板、任务、测试和说明；先报告问题、根因、影响与修复方案，获批后修复审计发现的全部问题并重新验证，不得用单点检查冒充完整审计。
20. `20 工作/29 SOP` 只由本人维护。本人在专题、典型案例话题或反复出现的工作问题上积累足够经验后，亲自总结成熟 SOP。AI 和自动整理不得向该目录新建、归类、移动、追加、改写或合并笔记，也不得把其中笔记作为自动更新候选；允许维护基础属性、索引、搜索和引用，但不得因此改变正文。

21. 所有文件夹名称必须遵循“两位数字编号 + 名称”规范：`NN[.M[.K]] 名称`（如 `22 项目与任务`、`22.2 计划与执行`、`22.2.1 里程碑与行动`）。顶层、中类与叶子目录均须遵守；分类目标以本 Vault `90 系统/92 维护规范/taxonomy.json` 为唯一权威，新增或调整目录结构必须先在 taxonomy 登记并保持编号连续、无重复。例外：程序生成的 `*-附件` 目录、按日期组织的存储目录（如 `95 原始输入归档/YYYY/MM/DD`、`94.1 整理记录/YYYY/MM`）不强制编号。定期清理到期归档原件的结果不再写入整理记录，而是独立记入 `90 系统/94 维护记录/94.6 清理记录` 的当日文件。
